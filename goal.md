# Project Goal

1. Deliver a working, verified application binary by following the `plan → task → verify → completed` workflow and using TDD. Keep production code and tests in separate `src/` and `tests/` trees, and keep every individual file at or below 300 lines.
2. Record collaboration in AgentMemory and commit/push each completed unit. Publish a GitHub release with macOS and Windows binaries when the binaries are ready for distribution.
3. Apply a systems-architecture method from requirements analysis through implementation: `Requirements → Business Goals → System Features → Use Cases → Functional/Non-functional Analysis → QAS → Design Drivers → System Architecture`.
4. Register each newly requested enhancement as a GitHub issue with the `enhancement` label. Reflect it in requirements and design documents before implementation. Implement reported GitHub issues, bugs, and enhancements; prioritize bugs over enhancements, and within each class take the oldest actionable issue first. Keep blockers explicit and close issues only after verification.
5. Write all project documents in English; communicate with the user in Korean.
6. Make active use of RTK, Ponytail, Graphify, and CocoIndex.
7. For each completed unit, record the work in AgentMemory and curate reusable knowledge using the llm-wiki approach.
8. Continue implementation and verification until the requested deliverable is complete; do not treat an intermediate code change or an unverified build as completion.
