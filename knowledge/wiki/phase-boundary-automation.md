# Phase boundary automation

Issue #943 amends DD-62.

A completed Phase is evidence, not a promise that the original next tasks remain correct. Re-plan one Phase from the Goal, analysis, remaining tasks and hash-verified merged diff/tests/final responses. Keep the original plan and every later Phase intact until approval/adoption. Do not return private profile environments in UI comparison metadata.

An unchanged effective task list can continue only with unchanged execution settings and the same repository-base/scope/permission checks. Treat order/model/fallback/options as execution changes. Automatic merge is a separate default-off consent bound to the executed plan and exact tested candidate. Never translate a CLI success into permission to bypass failed gates.

Reuse existing child-process jobs and state updates. Stop persists a chain pause across planning, approval and next-run boundaries. A fixed human revision belongs to its original request: after a resumed job changes state, perform automatic merge in a fresh job rather than weakening the immutable revision guard. Failed unchanged attempts must not spin on every snapshot.

Stream hashes of full test logs while passing bounded excerpts to the coordinator. Preserve explicit truncation and fail on altered evidence. Only backfill older outcome receipts from exact retained Goal-root links; never guess another Goal's results.

See `docs/evidence/943-whole-app-validation.md` for verification and limits.

#952: Windows refuses fixture deletion while a test-owned SQLite Store is alive. Explicitly drop the Store after its last assertion and before removing the fixture; do not ignore deletion errors or weaken merge assertions.

#954: Automation toggles must use a boolean-only, revision-bound native request; never capture/save the whole Workspace or clear dirty edits. Global input flex rules can stretch checkboxes even when width is fixed, so pin their flex basis and let explicit hidden styling override a flex label.

#959: A reviewed fallback changes task agent/model/fallback and appends handoff context, invalidating a whole-plan digest. Carry an existing exact opt-in only at trusted automatic fallback call sites, and audit both digests. Never reauthorize missing/disabled/mismatched consent or manual reassignment. Preserve review/permission/Stop/test gates. A false background merge outcome must report its pause reason rather than complete silently; expose it separately from the current human action job.
