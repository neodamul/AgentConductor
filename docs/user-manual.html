AgentConductor User Manual

Version 0.1.36 · 한국어 · Short introduction

Part 1 — Desktop application

1.1 Requirements and installation

Use macOS 11+ on Apple silicon, or Windows x86_64. Install Git and at least one coding CLI, already signed in: Claude Code, Codex, OpenCode or your company CLI. Projects can be ordinary folders; a Git repository and initial commit are optional. There is no model API key registration or local UI web server.

Download your platform archive and SHA256SUMS from GitHub Releases. Verify the archive, extract it and open AgentConductor.app or agentconductor.exe. Packages include the standalone executable, both manuals, screenshots, dependency licenses and SBOM. The app version is beside the title. Version 0.1.36 adds coordinator triage of failed tasks (the coordinator reviews the output, revises the task and resumes the run before asking you) and step lessons: what a coordinator revision, a replaced test command or an approved scope change taught the run is listed under Lessons, given to every later task as evidence and queued for agentmemory. Public release packages keep the numeric version and reject local labels.

1.1a Application updates

The app checks GitHub Releases in the background every 10 minutes. A newer installable release shows an update icon left of Settings. Choose Workspace ▾ → Check for updates, read the scrollable release notes beneath the link, inspect the current/latest versions and choose Update and restart. Finish or stop runs and active app jobs first; the desktop refuses installation while any saved workspace has running work.

Settings → Update repository chooses where updates come from: a GitHub owner/name, or an https://host/owner/name URL of an in-house GitHub-compatible server. Leave it empty for the default. Release notes, the archive and SHA256SUMS come from that repository's latest release, so only use a repository you trust.

The installer downloads the matching macOS/Windows archive and its SHA256SUMS, checks the archive hash, replaces the executable or macOS bundle and restarts with the same arguments. It needs curl, access to GitHub and permission to write the installation location. On failure, inspect the update dialog; do not assume a newer version was installed.

agentconductor update installs a newer release over the executable without restarting it; finish or stop work before running the command. The current updater makes unauthenticated GitHub requests and does not reuse GitHub CLI credentials: private or restricted releases require manual download with your authorized browser or GitHub CLI. Do not add model API keys for application updates.

1.2 Workspaces and settings

You can create, open and switch workspaces while planning or a run is in progress. The previous workspace keeps working in the background; reopen it from the workspace menu to read its current plan, progress and logs. Saved settings and execution evidence stay with that workspace. Switching does not stop or approve work. Finish or stop active work before deleting its workspace. Export/import continues to share the reviewed workspace configuration archive; it does not transfer live processes.

A workspace holds goals, plans, role assignments and local history. Name it, choose an existing project folder with Browse… or type the path, then Save workspace. Git worktree isolation is optional; shared execution is the default. Saving updates the name in the titlebar immediately and selects Agent roles. Tab changes preserve draft inputs; unsaved changes still require Save workspace.

Use Workspace ▾ to create, open or switch workspaces, edit plan rules, share settings, or configure messenger notifications. The same titlebar is available in Agent Room. A workspace with an existing run opens its work view when appropriate; returning to Workspace does not start a new plan. Unsaved changes require a choice before navigation.

Delete is available for the current workspace too. If planning is active, Stop planning and delete waits for its owned process and admitted metadata. Deleting the current workspace opens the most recently used remaining workspace; if none remains, the app creates an empty one. Active implementation requires Stop run first. Only saved app-owned workspace data can be removed; the project is preserved. Data moves to ~/.agentconductor/workspace-trash/<id> for recovery. Remove from recents hides an entry without deleting it.

Choose Ask coordinator on the Workspace screen to open a side chat. It reads the project and this manual with the coordinator's verified read-only CLI profile; it cannot write files or run commands. A coordinator must be registered. Chat uses the single background-operation slot shared with planning, and its conversation stays in the current window.

Use Workspace ▾ → User manual for offline help in the current interface language. HTML manuals preserve tables, code, links and screenshots. The standalone HTML manual can also be opened separately.

Settings includes:

  • Interface language: English or 한국어. Typed goals, prompts and raw evidence are never translated.
  • Theme: Light (default, neutral surfaces with a blue accent) or Dark (sage accents on dark surfaces). Save to apply immediately. The choice is stored with language in ~/.agentconductor/preferences.json and follows you across workspaces. Both themes retain the same controls and information.
  • MCP servers…: OpenCode-shaped JSON/JSONC command or remote definitions; use environment references for credentials. Select a server to edit settings or inspect its catalog; the registered coordinator chooses Jira/Confluence read tools. MCP guide.
  • Signal transport: Local Rust (default) or agentmemory preferred, with local fallback. The server port appears only for agentmemory; switching to Local Rust preserves its value.
  • Clear cache…: review paths and sizes before permanently removing eligible disposable metadata.

The workspace menu includes Agent tools guide… for optional agentmemory, RTK, Ponytail, Graphify and CocoIndex installation instructions. These tools are not bundled or required by the app.

1.3 Agents and models

The app-owned workspaces share one machine-wide CLI list, ~/.agentconductor/agents.json. Deleting a workspace does not remove this list. Role assignments belong to each workspace. Drag cards or use Move up/Move down to reorder agent selections. An assignment to a missing agent is highlighted and prevents planning until corrected.

Use + Add for Claude, Codex, OpenCode or Custom. Edit uses a pencil; Remove uses a trash icon.

  • Executables are found asynchronously; Browse… selects a file when discovery fails.
  • Arguments are a JSON array. The CLI keeps its existing authentication.
  • Capabilities follow the executable and invocation rather than a permission dropdown. Standard Claude and Codex profiles run with full access by default, bypassing their native permission prompts. Changed/custom executables do not inherit that capability. Custom CLIs handle their own tool approval by default; explicitly read-only or external-sandbox profiles keep those restrictions.
  • Each profile supports up to three sessions and a quota group for a shared account.
  • Set a fallback and its model. Mutual fallbacks are allowed; the engine stops after trying each agent once.
  • Models load without a generation prompt where supported. Models refreshes the observed list. A company CLI without discovery uses operator-configured model IDs; {model} must map to its actual argv option.
  • Quota refresh defaults to 5 minutes, configurable independently from 1–60 in Edit.

Custom CLI profiles can configure a manual model catalog or an explicit discovery command with JSON Pointer mappings. Declarative argument groups support allowed values, optional defaults, model-specific restrictions, and per-task overrides; an unset group is omitted from argv. Result JSON Pointers and pointer/value error conditions normalize custom result events. These fields are editable in the Rust agent profile dialog and are retained by workspace export/import. Existing built-in CLI adapters keep their established behavior. Custom profiles can also map JSONL event names and session IDs or configure a direct-argv quota command. See custom CLI profiles for configuration examples and limits.

Saving Use profile is asynchronous and closes after success; validation errors stay in the dialog. Changing execution settings requires reviewing a plan again. Metadata-only refresh does not invalidate it. One metadata collector runs at a time; queued requests do not block unrelated editing.

Saving a custom CLI applies the mode in which the CLI approves its own tool use automatically; no checkbox is needed. Plan and final merge approval remain required. Explicit read-only or external-sandbox profiles retain their restrictions.

A pressed button retains its working indicator until the request and its admitted background job finish, rather than appearing merely disabled.

1.4 Goals, sources and roles

Use one workspace per project folder. After finishing a goal, press New goal; the project, agents and roles remain, while the previous proposal, approval and applied source bindings are cleared. Enter and save the next goal, then generate or write a fresh plan. The goals card keeps prior slugs and progress; Select goal restores that goal and its recorded run for review. Finish or stop a nonterminal run before changing goals within the same project. Switching to another project workspace can keep its active sessions running.

If a new workspace chooses a folder already owned by another workspace, saving reports the existing owner and leaves the form unchanged. Switch to that workspace from the menu and use New goal. Existing duplicate data is retained; new planning/execution uses the deterministic primary workspace. Imported goal archives do not inherit another machine's run paths or execution approval.

Use the persistent Workspace settings, Agent roles and Review the plan tabs. Switching tabs preserves unsaved inputs; only Save workspace or Save plan edits persists them. Planning completion selects the review tab automatically. Describe the goal and choose the planning coordinator. Insert explicit jira:EMM-52599 and confluence:53553565 references after registering MCP servers. Preview and apply selected documents before planning. Large sources are saved as full local Markdown, summarized by the coordinator and checked against their hashes; source changes require renewed review. Registration alone does not run an MCP command.

Roles include verification, development, documentation, knowledge assetization and testing. Choose agents and optional models/alternates. Suggest defaults uses the registered team. The coordinator proposes scoped work following these assignments; the Rust engine owns execution and state.

Each goal has a short English slug, such as ladder_game, translated from the goal rather than romanized. Goal folders are directly under the project, <project>/<goal>/; ordinary-folder history remains app-managed. Existing older goal folders migrate when used. The goal tree contains plan/, phase/, task/, verification/ and completed/. Do not edit progress files by hand; the app checks their identity.

The project folder is above the goal; the coordinator is beside the workspace name. jira: and confluence: references become tags with hover summaries and delete like text. MCP lookups show progress; Preview opens immediately, then fills with the lookup result.

The menu places Export workspace beside Import workspace. Review transferred configuration on the destination machine; local secrets and verification claims are not blindly copied.

1.5 Plan and approval

Generate plan reads a temporary snapshot and requests analysis plus ordered phases. Claude and Codex planning use native JSON Schema output contracts; OpenCode and custom CLIs receive the same contract in their prompt. Phases, tasks, file scopes, dependencies and test arguments remain arrays. Invalid replies still fail validation and never approve execution. The app manages --json-schema / --output-schema; leave those flags out of registered profile arguments to avoid a schema conflict. The retained output-schema.json beside the planning prompt helps diagnose output errors. Generate plan clears the previous visible failure immediately and selects Review. The current coordinator CLI icon pulses without status color; progress follows the new job. Preparation shows elapsed time before the coordinator starts. Disabled approval shows its reason: save actual edits or wait for the active job. Reverting edits does not block approval. A failure keeps its cause in Review the plan; expand Error details to inspect and copy the retained CLI or parsing output before retrying. Logs remain available. Read plan… converts an existing Markdown plan (up to 64 KiB), skipping completed work. Write plan manually launches no coordinator; fill scoped tasks and test commands yourself.

Review every proposed phase up front. Phase headings identify its order and stage; expand folded task details to edit instructions, agent/model, owned files, dependencies and tests. Use Save plan edits, then Approve plan & run for the current phase. Before anything starts, a launch gate checks that every agent and every task's test command can be found (on PATH, as an absolute path, or inside the project); if not, the run is refused with each problem listed by code (tool_missing, test_unrunnable), the task and the missing name, so you can install the tool or fix the plan. A script that a task is asked to write inside its own paths is not counted as missing. A passed gate appears among the coordinator's judgments. Unfilled/overlapping tasks, a changed baseline or stale digest prevent approval. If the coordinator returns overlapping file scopes inside a generated phase, planning retries once with the exact validation feedback; overlap is still rejected if the corrected plan is invalid.

Goals & progress shows each goal's phase tags and description. After integrating a phase, Plan phase n loads the next saved phase without another planning call. Replanning an existing phased goal loads its current phase with current profiles. Plan rules… supports machine-wide rules or a workspace override.

For an ordinary folder, planning uses a temporary snapshot. Approved shared execution works directly in the selected folder, using Git metadata under ~/.agentconductor/project-history/ without creating .git in the project. Worktree mode isolates execution instead; review the candidate before applying it. Once the run is merged or rejected, its worktrees are removed from the repository; the diff, test results and logs stay in the run folder. Shared execution changes are already visible while agents work. For a committed repository a clean baseline is required. Review the dialog before Commit and continue. OS files can be ignored locally without changing .gitignore. Shared ordinary-folder execution uses existing local dependencies. Worktree execution needs its own dependency setup. The planner is told whether the project uses Git. For ordinary folders it proposes direct-file or project-runner checks instead of Git-dependent tests; any retained Git test command resolves through the external history. If evidence shows a test command cannot work here, the coordinator can replace it with a command verifying the same work, records the old/new command and reason, and reruns verification. It must not weaken a test that can run. Final candidate approval remains yours.

1.6 Agent Room and feedback

The status banner explains the run state, task/phase progress, failure cause and next action. After tasks pass, the stage rail continues through Verify, Merge and Workspace finalization; while an approved candidate is merging, the primary action shows "Merging approved changes" and stays disabled. Session rows show the reviewed task summary and task ID first, followed by the small agent icon, agent name and status tag. Long or translated statuses wrap within the rail. The left list uses green/yellow/red lights; running lights pulse and tasks awaiting a decision blink. Reduced-motion settings suppress animation. Usage badges stay in workspace agent cards, so the task list remains compact. The Account capacity inspector also shows Enterprise allocations as a remaining percentage. An outline identifies the selected task. Switch freely between Workspace and Agent Room during a run. The room retains live progress and the workspace back-to-run button shows the run state.

Select a task for Activity, Diff & tests, Raw logs or Lessons. The task details column on the right folds with the › button and the choice is remembered; when the run needs your decision it opens by itself with the candidate review on top, and if you fold it again a blinking dot on the strip reminds you until you decide. Every judgment the coordinator makes (tool decisions, review verdicts, replaced test commands, automatic resumes, recoveries, hand-offs, lessons) is listed in the coordinator view and in the activity of the task it concerns, and the coordinator row shows how many there are; nothing is hidden and it cannot be turned off. Lessons also lists what earlier steps taught the run (a coordinator revision, a replaced test command, an approved scope change); every later task receives the same lessons as evidence in its prompt, and they are queued for agentmemory. Activity displays messages, tool lines and result summaries; raw JSON remains in Raw logs. While a task runs, a line under its header shows the tool in progress with its elapsed time, the age of the last output and whether the agent process is present. It reports elapsed time only: silence is never labelled thinking or failure. Running tasks pulse their agent icon unless reduced motion is set. Thinking sections can be folded; silence/stall warnings report observation limits rather than prove failure. The coordinator is a selectable entry after tasks, showing integration steps, decisions and test output. When the session you are watching finishes, the selection moves to the next running session, or to the coordinator entry when the run waits for your approval; a finished session you selected yourself stays selected.

  • Send feedback (⌘/Ctrl+Enter) revises one task. An idle run continues after feedback is recorded. While a task is running, Send feedback is enabled for that task and queues the message for its next attempt.
  • Fix with feedback selects a failed task and drafts feedback from its failure output.
  • Reassign agents or change observed models through the task inspector; existing work/logs remain. A task that has not started yet can be changed while other tasks run; the change is queued and applied just before the task starts.
  • Resume at schedules an unavailable session. Stop run, Resume and Recover manage owned work.
  • Brief team summarizes assigned work, latest activity, freshness, restrictions and next actions.
  • Ask the coordinator (the ? button in the title bar) opens a side chat on the workspace screen. Ask how to run or use what was built, where results are, or how to use the screen; the coordinator reads the project, its plans and this manual, and answers with commands for you to run. It is read-only: it never changes files or runs commands, it needs a registered coordinator, and it shares the single background-operation slot with planning.

On reopening, automatic recovery checks that the interrupted run and its owned processes are quiescent before continuing unchanged work. It permits at most two attempts without new task progress. Explicitly stopped runs stay stopped, unknown ownership prevents recovery, and candidate approvals are revoked. Inspect the retained evidence if recovery cannot proceed.

In ordinary-folder projects, new files outside every owned task scope are moved to <RUN>/stray-files/ before integration and recorded, for example a CLI’s .aipro/plans. Existing operator files are preserved. Git repositories do not use this automatic move.

If a finished run fails with out-of-scope change, feedback cannot widen a task's owned paths. Choose Review recovery plan on the failed run: it lists every offending file, each task's approved paths and the files moved to stray-files; edit the owned paths and the test command, Preview change (it validates overlaps and shows which moved files would be restored, never overwriting a different file; the recovery copies stay), then Approve plan change and press Resume. Finished work is reused, earlier evidence is kept and integration verification runs again.

1.7 Tool decisions and verification

The following tool gates apply to guarded native_callback profiles. Standard full-access Claude/Codex profiles bypass native per-tool prompts; plan review and final candidate approval still apply.

Routine guarded Claude reads, edits, searches, builds and tests confined to the permitted workspace can run immediately. Unsupported or unsafe requests are refused before evaluation. Other requests are sent to the workspace coordinator for an allow/deny decision, recorded with its reason. If the coordinator cannot return a valid decision, a person is asked. The coordinator uses existing CLI authentication; it is not a new API service.

The tool request window shows a readable action, exact input under Raw input, live activity and the deadline. Allow once, Deny or Decide later controls pending human decisions. Approvals bind task, session, plan, workspace and input, expire within 900 seconds and are consumed once. Waiting for a tool decision is excluded from the task time limit. A timed-out task retries automatically after a bounded backoff; Stop cancels a pending retry. Use Resume for a stopped or terminally blocked run. Tool decisions do not approve integration.

Review Diff & tests. A changed verification report containing a Blocking/차단 section fails integration for the responsible task. Fix it and rerun verification. Large patches show a shortened preview and a command such as agentconductor diff "<run-directory>" for the complete patch. Truncation alone does not disable approval: verification hashes the entire patch, including omitted lines. Inspect the complete diff before approving when needed. Approve binds the exact candidate, baseline, complete diff hash and passing tests. Then use Merge approved candidate for Git, Accept changes for direct ordinary-folder execution, or Apply changes for legacy private-copy runs. Rejecting a direct-folder candidate restores owned files to their recorded baseline only when later manual edits would not be overwritten. Any changed evidence revokes approval. Only the human approves final integration.

When all tasks complete but integration verification fails, the recorded coordinator can review evidence, revise affected tasks and rerun them. Repair stops after three review rounds or an invalid response; then revise or reassign the work yourself.

1.8 Quota and fallback

Paid CLI cards display reported remaining capacity, for example 64%/100% ↻. Automatic Claude usage queries wait until you save a project folder. Saving the first folder or changing the saved folder resets Claude’s refresh schedule for a fresh background query, even after a previous empty-folder failure; saving the same path does not reset it. Codex keeps its account refresh schedule. Folder selection alone does not grant trust or execution permissions. Enterprise metadata uses remaining/allocated percentages; rolling windows use the provider's labels (5h/weekly, daily/weekly, etc.). Hover for raw amounts, reset time, source and freshness. Credits without a known allocation do not imply a percentage. Token counts/cost estimates are not account balance. Unavailable shows —; stale observations suppress percentages. Exhausted windows keep percentages compact; their reset time appears in the tooltip.

A transient at capacity or model-overload reply waits about 60 seconds and retries up to three times, for tasks and the coordinator. This is separate from subscription exhaustion.

Queries run asynchronously with bounded output and deadlines, without generation requests. Claude uses an isolated metadata session with tools/hooks/project settings disabled; its folder-trust prompt can be answered only in that restricted collection session. Theme/login setup must be completed in the CLI. Codex requires its existing ChatGPT login. Actual Enterprise formats and a company CLI still require operator acceptance.

Claude metadata collection recognizes $, > and ❯ prompts and its known folder-trust choices. Enterprise /usage spent/allocated amounts are normalized to remaining/allocated percentages; raw amounts remain available in the tooltip. A date without a clock is not an exact resume reservation. Timeout messages distinguish a missing prompt from no response after /usage.

A reported restriction applies to the quota group. An explicit reset prefills Resume at and shows a countdown. An independent coordinator stores the reservation and resumes at that deadline, even after the app closes. Reopening restores a missing coordinator; reassignment cancels the old reservation, and Stop cancels automatic continuation. If the reset requires more than five hours of waiting, the coordinator uses only the fallback in the reviewed plan. With no known reset, that policy applies five hours after the original restriction. Without an available planned fallback, the task waits. Unknown timezones are not guessed; use Resume at to specify a time. The inspector shows the scheduled local time and remaining countdown, or a paused-timer reason. You can override the prefilled time. Up to three automatic resume attempts are admitted; changing a manual schedule renews the retry allowance. Reservation ownership belongs to the lightweight Rust coordinator, not an LLM session or a browser timer; only one watcher owns each run. Inspect retained evidence before restoring a reservation with unknown process ownership. A transfer starts a new provider session after the current owner exits; files and logs remain. Authentication/configuration errors are not automatically retried. Transfers require fresh verification and approval.

1.9 Memory, sharing and cache

Local SQLite checkpoints and audited decisions remain authoritative. A cooperative custom CLI polls at safe boundaries; registering it does not give an arbitrary CLI live steering support. Local Rust never contacts agentmemory. agentmemory preferred records one external attempt; if unavailable or uncertain after restart, it retains the same local directive without replay. The client has an 8-second bound. A stored memory receipt is not recipient acceptance. These options do not deliver to agents on another computer.

Reviewed lessons include evidence and source hashes, are mirrored to Markdown wiki assets, and become stale when their source changes. They grant no permissions. Manual memory sync/import is optional.

Export workspace… shares profiles, roles and verified goal archives. Secrets, environment values and local model observations remain on the machine. Review archives before sharing; imported capability claims require local confirmation.

Messenger… supports Slack/webhooks and optional allow/deny replies from listed approvers. Webhook/bot tokens and relay secrets stay local. Goal text is included only by explicit choice. Remote replies never approve a plan or merge.

Clear cache… previews eligible completed query/metadata/catalog files. Permanent removal cannot be undone. Live/unknown/aliased data, current diagnostics, source folders, reviewed plans, diffs, tests, audit and workspace recovery remain. Eligible cache is trimmed to eight newest folders plus protected references at idle startup/settlement. There is no resident cleanup daemon. Cargo build output is separate from application cache.

Part 3 — Validation and troubleshooting

The packaged native executable is checked on macOS and Windows using deterministic offline workers, including Git/ordinary-folder projects, shared/worktree execution and refused unapproved integration. This does not establish acceptance of your company's agent, Enterprise account or live messenger.

Previously exercised CLI contracts: Claude Code 2.1.287; Codex 0.162.0 tasks/resume and 0.162.1 quota metadata; OpenCode 2.0.25; agentmemory server 0.9.29. Installed provider versions may differ. Unknown output stays unavailable or fails safely.

  • Missing executable / Windows error 193: use the actual native or npm .cmd launcher; Edit → Browse can override discovery.
  • Quota unavailable: inspect the tooltip, finish CLI theme/login setup and refresh. No allocation means no invented percentage.
  • Missing role agent: select a registered agent for every highlighted assignment.
  • Dirty baseline: inspect listed files before committing, stashing or choosing Stop.
  • Blocked/failed run: inspect the cause and test output; Fix with feedback, correct configuration and Resume.
  • Interrupted ownership: Recover only after owned processes are confirmed gone. Reopening permits bounded automatic continuation only after verified process absence; manually stopped runs remain stopped.
  • Changed source/approval: plan or verify again. Ordinary-folder application has backups and a receipt; interrupted application is not replayed blindly.
  • MCP timeout: inspect the registered command/server and its bounded timeout; keep raw logs private.
  • Window already open: use or close the existing window rather than opening another.

Codex reconnects in Enterprise networks

AgentConductor keeps explicit reconnect attempts and WebSocket-to-HTTP fallback notices as visible warnings; a successful final turn can continue planning and execution. Terminal failures, missing final output, failed exit codes and timeouts remain failures.

If your company network repeatedly blocks WebSockets, merge this into %USERPROFILE%\.codex\config.toml (or $CODEX_HOME/config.toml when set). Put model_provider before the first TOML table; update existing keys instead of duplicating them. The provider table name is model_providers, plural. Existing CLI sign-in is retained; no API key is added. Restart Codex sessions after saving.

Signals and optional helper tools

Workspace Settings selects Local Rust or agentmemory preferred. Installing an optional helper does not select a backend. Local Rust needs no agentmemory MCP tool or server; workers report through their normal CLI output. The app owns signal delivery and durable evidence. Registered checkpoint workers use the exact executable path supplied by the app and its local poll/ack/report commands; other CLI sessions must not invent checkpoint capabilities. A missing optional memory tool is not a task failure.

Windows path selection uses the standard Common Item Dialog directly, with no PowerShell or C# startup. Cancel leaves the field unchanged; choosing a folder or file fills the field and saving validates it.
